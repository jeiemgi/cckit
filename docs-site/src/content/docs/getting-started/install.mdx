Every step of the process is one `cckit` command, and every one of them talks to GitHub. So before
a project can be set up, the machine needs two things: the command itself, and a GitHub sign-in it
can use. This page gets you both and has cckit check its own work.

**What you will have at the end:** `cckit` answers in any folder, `cckit doctor` reports nothing
missing, and `gh` is signed in to GitHub. No repository has been touched yet.

## Steps

<Steps>

1. **Confirm your platform is supported.**

   | Platform | Supported |
   | -------- | --------- |
   | macOS    | Yes, native |
   | Linux    | Yes, native |
   | Windows  | Yes, through WSL or Git Bash (not native cmd or PowerShell) |

   The command-line tools it needs are checked for you in step 4.

2. **Install cckit.** Each tab is one way to do it. Pick one and copy the box.

   <Tabs syncKey="install-method">
     <TabItem label="One-liner">
       ```sh title="macOS · Linux · WSL — no npm or brew"
       curl -fsSL https://cckit.dev/install.sh | bash
       ```
     </TabItem>
     <TabItem label="Homebrew">
       ```sh title="Formula/cckit.rb"
       brew install jeiemgi/cckit/cckit
       ```
     </TabItem>
     <TabItem label="npm">
       ```sh title="the bare name is taken, so cckit is scoped"
       npm install -g @jeiemgi/cckit
       ```
     </TabItem>
     <TabItem label="From source">
       ```sh title="symlinks bin/cckit onto your PATH"
       git clone https://github.com/jeiemgi/cckit.git
       cd cckit && ./scripts/install.sh
       ```
     </TabItem>
   </Tabs>


3. **Confirm the command is there.**

   ```sh
   cckit version       # prints the installed version
   ```

4. **Let the doctor check the rest.** You need `bash`, `git`,
   [`gh`](https://cli.github.com/) (the GitHub command-line tool), `jq` (a JSON reader) and
   `perl`. `cckit doctor` finds what is missing and, **when you run it in a terminal, asks
   before installing anything**:

   ```bash title="Check what is missing, and offer to fix it"
   cckit doctor
   ```

   Say yes and it installs each piece for you (Homebrew, `gh`, `jq`, …). Say no and it prints the
   exact commands to run yourself. Run where there is no terminal to ask in (from an agent, a
   script, CI) it installs nothing and writes no file, and says so on its second line. To skip the
   question, use `--fix`:

   ```bash title="Install the missing pieces without the prompt"
   cckit doctor --fix
   ```

5. **Sign in to GitHub.** Once `gh` is installed, authenticate once:

   ```bash
   gh auth login
   ```

</Steps>

<Aside type="tip" title="New to the terminal? Start here">
The terminal is the text window where you type commands. [`gh`](https://cli.github.com/) is GitHub's
official command-line tool. Run `cckit doctor`, approve the prompt, and it installs `gh` (and anything
else missing) for you; then `gh auth login` signs you in.
</Aside>

## Check it worked

Run the doctor once more:

```bash
cckit doctor
```

It should report `git`, `gh` (authenticated) and `jq` as present and list nothing left to do. If a
row is still missing, the doctor prints the command that fixes it.

## How the install works

cckit is bash scripts over `git`, `gh` and `jq`. There is no build step: installing it puts the
`cckit` dispatcher on your PATH, the list of folders your terminal searches when you type a
command.

`cckit install [bin-dir]` symlinks `bin/cckit` into the first writable PATH folder (`~/.local/bin`, then `/usr/local/bin`, then `~/bin`), or a folder you pass.

With the one-liner and the "From source" route it is a **symlink, not a copy**: the dispatcher resolves the link back to the cloned repository, so `git pull` there upgrades your install with no reinstall.

That also means such an install is as old as the branch its clone is parked on. The [install and update matrix](/install-matrix/) compares every route: what lands on disk, how it updates, and when a restart is needed. [Many sessions, one repository](/development/many-sessions/) covers a clone that several agent sessions share.

## What it depends on

| Required | Why |
| --- | --- |
| `git`, `gh`, `jq` | the work itself: worktrees, GitHub, JSON |
| `perl` | `cckit init` stops without it; headless agent runs use it to bound a round |
| `bash` 3.2+ | the dispatcher and its libraries |

Optional, auto-detected, never required:

| Optional | Enables |
| --- | --- |
| `tmux` | the default `cckit orchestrate` runtime |
| `herdr` | persistent, state-aware orchestration with `--runtime herdr` |
| `glow` / `fzf` / `gum` | nicer terminal output and pickers |
| Node + Chrome | `cckit debug` (browser debugging via chrome-devtools-axi) |

`cckit doctor` reports what is missing, including the agent CLI (`claude`, `codex`) of each adapter
the project selected. `cckit doctor --agents` prints only those rows and makes no network call.

<Aside type="tip" title="What is a symlink? (skip if you know)">
A symlink is a pointer file: it stands in one folder but redirects to a file somewhere else. cckit installs as a symlink into a PATH folder that points back to the cloned repo, so updating the repo updates your installed command automatically.
</Aside>

Every step of the process is one `cckit` command. The core runs on git alone; the verbs that write
issues and pull requests reach GitHub through a token. So before a project can be set up, the
machine needs the command itself and, for those verbs, a GitHub token it can use. This page gets you
both and has cckit check its own work.

Each step starts with the sentence you say to your agent in the chat. Below it is the command your
agent runs for that sentence, and what it printed, pasted from a real run on the Bakery site, the
example project of these guides. You can type any command yourself.

**What you will have at the end:** `cckit` answers in any folder, `cckit doctor` reports nothing
missing, and its `forge` row says `github — signed in as @you`. No repository has been touched yet.

## Steps

## 1. Confirm your platform is supported

| Platform | Supported |
| -------- | --------- |
| macOS    | Yes, native |
| Linux    | Yes, native |
| Windows  | Yes, through WSL or Git Bash (not native cmd or PowerShell) |

The command-line tools it needs are checked for you in step 4.

## 4. Let the doctor check the rest

You need `bash`, `git`, `jq` (a JSON reader), `perl` and `curl`. [`gh`](https://cli.github.com/),
GitHub's command-line tool, is optional: it is one way to get the token the next step needs, and
cckit uses its token when `GH_TOKEN` is unset. `cckit doctor` finds what is missing and, **when you
run it in a terminal, asks before installing anything**. The one-liner and the source install refuse
to run without `git`, and say how to install it.

    "  ✓  jq                           jq-1.8.2",

    "…",
    "  Summary",
    "       18 checked ok",
  ]}
  means="Run with no terminal to ask in, the doctor only reports: it installs nothing and writes no file. It says so on its second line."
>
  Nothing is missing: `git`, `jq` and `perl` are present, and `gh` is there too, which is optional.
  Because I ran this without a terminal, I installed nothing.
</Chat>

Run in a terminal, the doctor asks before it installs each missing piece (Homebrew, `jq`, `curl`, …).
Say yes and it installs it. Say no and it prints the exact commands to run yourself. Run where there
is no terminal to ask in (from an agent, a script, CI) it installs nothing and writes no file. To
skip the question, use `--fix`:

```bash title="Install the missing pieces without the prompt"
cckit doctor --fix
```

## 5. Give cckit a GitHub token

The verbs that write issues and pull requests need a token. Two ways to provide one; the doctor's
`forge` row tells you which is in use.

<Chat
  title="signing in to GitHub for the Bakery site"
  say="Sign this computer in to GitHub."
  ran="gh auth login"
  means="This one needs you. The command asks you questions and opens a browser to confirm the sign-in. cckit then uses gh's token."
>
  I started the sign-in, but I cannot finish it for you: it waits on a code and a browser window.
  Complete it in your terminal, then I will run the doctor again.
</Chat>

Without `gh`, put a token in the environment instead: `export GH_TOKEN=<token>`, a fine-grained
token with Issues, Pull requests and Contents on the repository. Until a token is in place, cckit
runs on git alone: `cckit start`, `cckit pr` (it pushes and prints the compare page), `cckit merge`
(through git) and `cckit gc` work and say in one line what they skipped; a verb that only exists on
GitHub refuses by name. The config page describes [the forge](/config-and-permissions/#the-forge).

<Aside type="tip" title="New to the terminal? Start here">
The terminal is the text window where you type commands. [`gh`](https://cli.github.com/) is GitHub's
official command-line tool and the easiest way to sign in: install it (`brew install gh`), run
`gh auth login`, and cckit uses the token it keeps.
</Aside>

  ran="cckit doctor"

    "  ✓  jq                           jq-1.8.2",
    "  ✓  perl                         is",
    "…",
    "  Auth + config",
    "  ✓  forge                        github — signed in as @jeiemgi",
    "…",
  ]}
  means="A row that is still missing prints the command that fixes it; the forge row names the GitHub login the token belongs to."
>
  Yes. Everything cckit needs is installed, the token works, and nothing is left to do.
</Chat>

It should report `git`, `jq`, `perl` and `curl` as present, the `forge` row as `github — signed in
as @you`, and list nothing left to do. A `forge` row that says `none — git-only` means no token was
found: the git verbs run, the GitHub ones refuse until step 5 is done. If a row is still missing,
the doctor prints the command that fixes it.

An agent that opens your repository for the first time knows nothing about how your team works. It
does not know which branch you integrate on, who owns a design question, or that work starts from
an issue. Ask it for a fix and it will edit files wherever it happens to be standing.

Setup is where you write that down, once. After it, every session starts from the same description
of the project, and every piece of work can go through the same steps.

## The three things a project needs

1. **The `cckit` command on your machine.** It is the one tool that runs each step: start a piece
   of work, open its pull request, clean up after the merge. You install it once per machine.
2. **Access to GitHub.** The plan and the record of the work live there, as issues and pull
   requests. cckit reaches GitHub through your own signed-in `gh` session and stores no token of
   its own.
3. **A profile of roles in the project.** A profile is the description of your team: which agents
   exist, which rules they follow, which skills they have. `cckit init` writes it into the
   repository, once per project.

Set them up in that order. Each step checks the one before it.

## Who does it

One person, once. It needs a terminal for a few minutes; after that the work can be done by talking
to the agent. In Claude Code the same steps exist as `/kit-doctor` and `/kit-init`, so you can ask
the agent to run them and answer its questions.

No agent role is involved yet. The roles arrive with the profile:
[The team: you and the agents](/philosophy/the-team/).

## The tools that plug in

cckit is a set of bash scripts over tools you may already have. It builds none of them.

- **`git`, `gh`, `jq` and `perl`** are required. `gh` is GitHub's command-line tool; `jq` reads
  JSON; `cckit init` stops without `perl`.
- **Claude Code or Codex** is the agent. You choose one or both at setup.
- **MemPalace**, for memory between sessions, is optional and off by default. It has its own area:
  [Memory](/memory/).

`cckit doctor` reports which of these are missing and asks before it installs anything.

## The commands

| Command | What it is for |
| --- | --- |
| `cckit doctor` | Check the machine: the required tools and the GitHub sign-in |
| `cckit init` | Set a project up: the config, the profile, and the git and GitHub steps |
| `cckit scan` | Report what a repository already contains, before anything is written |
| `cckit adopt` | Record the cckit files a repository already has, without changing them |
| `cckit update` | Say whether a project is behind the installed cckit |
| `cckit init --upgrade` | Bring a project to the installed version |

Every flag of these commands is in the [CLI reference](/cli-reference/).

Feedback on an interface is hard to put into words. "The second card, the padding under the
title, it is too tight" makes the agent guess which card, which file and which value. A person
reviewing a screen wants to point at the thing.

This guide sets up pointing. You click an element in your running dev app and leave a note. Claude
Code receives the note together with the element's CSS selector, its React component and a source
file path, finds the code and fixes it.

The capture tool is [Agentation](https://www.npmjs.com/package/agentation), third-party software
that cckit adopts and does not build. The `kit-annotate` skill installs it into your project and
wires it to Claude Code.

**What you will have at the end:** a toolbar in the bottom-right corner of your dev app, and a
Claude Code session that pulls the notes you leave, fixes each one and marks it resolved.

## Before you start

- **It is for React apps.** Next.js, Vite and React Router v7 are wired for you. Another React
  setup (Create React App, Gatsby) is installed and registered, and you add the toolbar line
  yourself. A project with no `react` in its `package.json` is refused.
- **It is for Claude Code.** cckit wires and maintains the Claude Code path only. Agentation can
  serve other agents through its own tooling; cckit does not set that up.
- **It runs in development only.** The toolbar is behind a development check and is not part of a
  production build.

<Outcomes title="The toolbar line, per framework">

For Next.js it looks like this:

```tsx title="app/layout.tsx"
import { Agentation } from "agentation";

// inside <body>, after {children}
{process.env.NODE_ENV === "development" && <Agentation endpoint="http://localhost:4747" />}
```

Vite and React Router use `import.meta.env.DEV` as the check, in `src/main.tsx` and
`app/root.tsx`. Keep the `endpoint` prop: without it the toolbar saves notes in the browser
only and Claude Code never sees them.

## Check it worked

- The toolbar shows in the bottom-right corner of the dev app.
- `npx agentation-mcp doctor` flags nothing to fix.
- After step 6, every note in the toolbar is resolved or dismissed with a reason, and
  `git status` in the project shows the files Claude Code changed.

## How it works

The MCP server receives notes from the toolbar over HTTP on port `4747` and hands them to Claude
Code. The port is stored as `annotate.mcp.httpPort` in the project config.

The rule file `.claude/rules/react-annotate.md` holds the loop the agent follows. It applies when
the agent works on a `.tsx` or `.jsx` file. For each note the agent acknowledges it, finds the
code, makes the fix and resolves the note with a summary. It dismisses a note it cannot act on,
with the reason, or replies to ask you a question.

By default the agent waits for you to finish and takes the whole batch. Ask it to "watch" if you
want notes picked up one by one as you leave them. `/kit-annotate status` prints the stored setup
and the active annotation sessions.

A note is about a design decision as often as it is about a bug. The
[design-routing rule](/design/) still applies: a note that asks for a new visual value goes to the
designer agent before code changes.

<Aside type="note" title="Agentation is not part of cckit">
Agentation is source-available software under the PolyForm Shield 1.0.0 license. It is installed
from its public npm package as your project's own dev dependency. cckit copies none of its code
and does not maintain it.
</Aside>

## Limits

- **A note identifies an element, not its data.** The agent receives the selector, the component
  name and a source path. It does not receive the values of props or state, so it searches the
  repository to find the exact code. A file and line are not guaranteed.
- **Server-rendered components give less.** A React Server Component is identified by its CSS
  selector only. Client components carry the full record.
- **The agent receives less than the toolbar shows.** If a detail is missing, press Copy in the
  toolbar and paste the result into the conversation.

## Troubleshooting

**Claude Code has no annotation tools.** The MCP server loads when Claude Code starts. Restart it,
then run `npx agentation-mcp doctor`.

**Connected, and zero sessions while you annotate.** The `endpoint` prop is missing from the
toolbar line, or the browser tab predates the setup. Add the prop as in step 4 and reload the tab.

**The setup stops with "No React app detected".** The project's `package.json` does not list
`react`. The skill does not cover other stacks.

**The setup could not register the MCP server.** Run the command it prints yourself:
`claude mcp add agentation -- npx -y agentation-mcp server`.

**You want it gone.** Delete `.claude/rules/react-annotate.md`, run
`claude mcp remove agentation`, and remove the toolbar line from the entry file.

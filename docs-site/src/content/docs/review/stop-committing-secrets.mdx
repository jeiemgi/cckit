An agent stages files fast and does not know which of them hold a key. Once a key is pushed it is
public, and deleting it later does not undo that. The cheapest place to stop it is the commit
itself.

**What you will have at the end:** a git **pre-commit hook** that scans every commit for keys,
`.env` files, private-key blocks and your own private terms, and blocks the commit when it finds
one. It applies to every commit in this clone, whether you typed it or an agent did.

What the guard checks is described in [The secret guard](/review/secret-guard/).

## Steps

### 1. Put the guard in the project

<Chat
  title="adding the secret guard to the Bakery site"
  say="Put the secret guard in the Bakery site, so a key can never be committed by accident."
  ran={[
    "git clone --depth 1 https://github.com/jeiemgi/cckit /tmp/cckit-src",
    "mkdir -p githooks scripts/lib",
    "cp /tmp/cckit-src/githooks/pre-commit githooks/",
    "cp /tmp/cckit-src/scripts/lib/secret-guard.sh /tmp/cckit-src/scripts/lib/kit-state.sh scripts/lib/",
    "cp /tmp/cckit-src/privacy-denylist.example .",
    "git add githooks scripts/lib/secret-guard.sh scripts/lib/kit-state.sh privacy-denylist.example",
    'git commit -m "chore: add the secret guard"',
  ]}
  means="cckit init does not copy the guard, so this takes the files from a clone of cckit. Run it from the project root, on a working branch. In a clone of cckit itself the files are already there: skip this step."
>
  The guard is in the project and committed on your working branch. It does nothing yet: the next
  step turns the hook on.
</Chat>

### 2. Turn on the pre-commit hook

<Chat
  title="turning the guard on for every commit"
  say="Turn the guard on, so it runs on every commit."
  ran="git config core.hooksPath githooks"
  means="You point git at the githooks folder once. From now on git runs the guard on every git commit, before anything reaches a remote."
>
  Done. Git runs the secret guard on every commit in this clone, yours or mine.
</Chat>

### 3. Prove it blocks a secret

<Chat
  title="proving the guard blocks a key on the Bakery site"
  say="Prove it works: stage a fake .env file for the mail service and try to commit it."
  ran={[
    'echo "API_KEY=sk-not-a-real-key" > .env',
    'git add -f .env && git commit -m "test"',
  ]}
  means="The guard prints x secret-guard: forbidden file must not be committed: .env, and the commit ends with commit blocked by secret-guard."
>
  The commit was blocked and nothing was committed. I'll unstage the test file and delete it:
  `git reset -q .env && rm .env`.
</Chat>

### 4. Declare your own private terms (optional)

<Chat
  title="adding the bakery's private terms"
  say="Also block the flour supplier's name and the owner's personal email."
  ran="mkdir -p .cckit && cp privacy-denylist.example .cckit/privacy-denylist"
  means="Beyond keys and env files, add anything private to you: org names, internal hosts, emails, one per line. The target is gitignored."
>
  The private list is in place and holds both terms. The guard now also fails a commit if either
  appears in a staged file.
</Chat>

## How to check it worked

`git config core.hooksPath` prints `githooks`, and the commit in step 3 ended with
`commit blocked by secret-guard` and created no commit: `git log -1` still shows the commit from
before the test.

## How it works

The pre-commit hook you just enabled scans the files staged for that commit. In cckit's own
repository the same guard also runs in the check suite (`scripts/check.sh`), which scans every
tracked file. A finding blocks the commit; it is not waved through by permission consent. Because it fires at
commit time, a leaked key is caught **before** it can reach a remote, whether you or your agent
ran the commit. The hook is bypassable: `git commit --no-verify` skips it, and the hook's own
message names that flag.

<Aside type="note" title="Why a pre-commit hook">
A pre-commit hook is a script git runs the instant you commit. If the script exits non-zero, the
commit is blocked — which is exactly the moment to stop a secret, before it leaves your machine.
</Aside>

## Troubleshooting

**The guard didn't run on my commit.** The hook path isn't set. Re-run
`git config core.hooksPath githooks` in the repo, and confirm with `git config core.hooksPath`.

**The commit prints `secret-guard not found, skipping`.** `scripts/lib/secret-guard.sh` is not in
the project. The hook lets the commit through in that case. Repeat step 1.

**It blocked a placeholder that isn't a real secret.** Placeholders like `<...>`, `${...}`, and
`YOUR_…` are allowed by design. If a real placeholder still trips it, rephrase it to one of those
forms rather than disabling the guard.

**My teammate's clone doesn't enforce it.** `core.hooksPath` is per-clone local config. Each person
runs the one-time command once, or you wire it in your setup script — the hook itself is committed in
`githooks/`.

**What you'll set up:** cckit ships a secret guard that scans every staged change for keys, `.env`
files, private-key blocks, and your own private terms. Turn it into a git **pre-commit hook** and the
commit is blocked the moment a secret is staged — whether you typed it or Claude Code did. It takes
one command.

## Steps

<Steps>

1. **Turn on the pre-commit hook.** cckit ships the hook in `githooks/`; point git at it once.

   <div class="cckit-prompt">

   ```bash frame="terminal"
   git config core.hooksPath githooks
   ```

   </div>

   From now on git runs cckit's guard on every `git commit`, before anything reaches a remote.

2. **Prove it blocks a secret.** Stage a fake `.env` and try to commit — the guard fails the commit.

   ```bash frame="terminal"
   echo "API_KEY=sk-not-a-real-key" > .env
   git add -f .env && git commit -m "test"
   # x secret-guard: forbidden file must not be committed: .env
   ```

   Nothing was committed. Delete the test file: `rm .env`.

3. **Declare your own private terms (optional).** Beyond keys and env files, add anything private to
   you — org names, internal hosts, emails — one per line.

   ```bash frame="terminal"
   cp privacy-denylist.example .cckit/privacy-denylist   # the target is gitignored
   # …add your terms, one per line…
   ```

   The guard now also fails a commit if any of those terms appears in a staged file.

</Steps>

## How it works

The guard runs in two places: the local check suite (`scripts/check.sh`), which scans every tracked
file, and the pre-commit hook you just enabled, which scans the files staged for that commit. A
finding blocks the commit; it is not waved through by permission consent. Because it fires at
commit time, a leaked key is caught **before** it can reach a remote, whether you or Claude Code
ran the commit. The hook is bypassable: `git commit --no-verify` skips it, and the hook's own
message names that flag.

<Aside type="note" title="Why a pre-commit hook">
A pre-commit hook is a script git runs the instant you commit. If the script exits non-zero, the
commit is blocked — which is exactly the moment to stop a secret, before it leaves your machine.
</Aside>

## Troubleshooting

**The guard didn't run on my commit.** The hook path isn't set. Re-run
`git config core.hooksPath githooks` in the repo, and confirm with `git config core.hooksPath`.

**It blocked a placeholder that isn't a real secret.** Placeholders like `<...>`, `${...}`, and
`YOUR_…` are allowed by design. If a real placeholder still trips it, rephrase it to one of those
forms rather than disabling the guard.

**My teammate's clone doesn't enforce it.** `core.hooksPath` is per-clone local config. Each person
runs the one-time command once, or you wire it in your setup script — the hook itself is committed in
`githooks/`.

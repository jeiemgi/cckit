A scanner can recognise an API key by its shape. It cannot know that a client's name, an internal
hostname or a colleague's email is private to you, and neither can an agent writing a commit
message or a fixture.

So you tell the guard. You write the terms in a list that stays on your machine, and the guard
blocks any commit that contains one.

**What you will have at the end:** a private list at `.cckit/privacy-denylist` that the secret
guard checks on every commit. cckit ships the list **empty**: it never guesses what is yours, and
nothing project-specific is in the kit.

**Before you start:** the guard has to be in the project with its hook on.
[Stop agents committing secrets](/review/stop-committing-secrets/) does both.

## Steps

<Steps>

1. **Copy the example denylist.** The target is gitignored, so your terms never get committed either.

   ```bash frame="terminal"
   mkdir -p .cckit && cp privacy-denylist.example .cckit/privacy-denylist
   ```

   Run it from the primary checkout. From a worktree, use the commands in
   [The secret guard](/review/secret-guard/#your-private-denylist), which resolve the one shared
   `.cckit/` folder.

2. **List your private terms.** One per line — org names, hosts, emails, anything private to you.

   ```text frame="terminal" title=".cckit/privacy-denylist"
   acme-internal
   vpn.acme.example
   jane@acme.example
   ```

3. **Prove it blocks them.** Stage a file that mentions a listed term and try to commit — the guard
   fails the commit.

   ```bash frame="terminal"
   git add . && git commit -m "test"
   # x secret-guard: private term 'acme-internal' present: <file>:<line>:<the matching line>
   ```

</Steps>

## How to check it worked

The commit in step 3 printed `secret-guard: private term` with the file and line, and no commit was
made. `git status --short .cckit` prints nothing, because the list is gitignored.

## How it works

On every commit the pre-commit hook passes the staged files to the guard, and your denylist is
checked alongside the built-in rules for keys and env files. The list lives in
`.cckit/privacy-denylist`, which is gitignored.

<Aside type="tip" title="This pairs with the built-in guard">
The denylist extends the same guard that already blocks keys, `.pem`/`.key` files, JWTs, and
secret-looking assignments — see [Stop agents committing secrets](/review/stop-committing-secrets/).
</Aside>

## Troubleshooting

**My denylist file got committed.** It shouldn't — `.cckit/privacy-denylist` is gitignored by
default. If you copied it elsewhere, move it back to that path so it's ignored.

**A term matches too broadly.** The guard matches the literal term, and upper and lower case
count as different. Choose specific strings (a full
hostname rather than a common word) so it doesn't trip on unrelated text.

**Nothing was blocked.** Confirm the file is at `.cckit/privacy-denylist`, the terms are one per line,
and the [pre-commit hook is enabled](/review/stop-committing-secrets/) with
`git config core.hooksPath githooks`.

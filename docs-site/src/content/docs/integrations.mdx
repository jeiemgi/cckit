An **integration** is an optional third-party tool that cckit can switch on, install and re-check.
Each one is a JSON file, `integrations/<id>.json`: its config key, its install commands in the order
they are tried, the command that proves it works, and who makes it. `cckit add`, `cckit doctor` and
the monthly check all read that file, and none of them holds a tool's recipe in code.

Every integration but one is off until you switch it on. With its key unset, no row is printed,
nothing is installed and no exit code changes. The exception is `lavish`, which is **on by default**
(`config.default: true` in its descriptor): with `reviewPages.enabled` unset the doctor prints its
row, installs nothing and changes no exit code, and `cckit add lavish --set enable=no` turns it off.

## The integrations that ship

| `cckit add …` | What it gives you | Config key | Offered where | Made by |
| --- | --- | --- | --- | --- |
| `mempalace` | Persistent per-project memory: sessions wake up with context and file their work back. | `memory.enabled` | any repo, any machine | [MemPalace](https://github.com/MemPalace/mempalace) |
| `mlx-lm` | A local model runtime: digest, summarize and classify run on this Mac through `mlx_lm.server`. | `local.enabled` | Apple silicon only (`Darwin` + `arm64`) | [Apple, ml-explore](https://github.com/ml-explore/mlx-lm) |
| `graft` | Code-graph retrieval: agents ask an index where code lives and who calls a symbol. | `codeGraph.provider` = `graft` | a repo with at least one file in a language Graft indexes | [NanoNets / Trail](https://github.com/trailhq/Trail-Code) |
| `impeccable` | Design direction for a page: plan it, set type, layout and colour, flag the look of a generated page. Step 1 of [`page-design`](/skills/#page-design). | `designDirection.provider` = `impeccable` | any repo; installed for Claude Code | [pbakaus](https://github.com/pbakaus/impeccable) |
| `emil-design-eng` | Interaction and motion rules for a chosen design. Step 2 of `page-design`. | `designMotion.provider` = `emil-design-eng` | any repo; installed for Claude Code | [Emil Kowalski](https://github.com/emilkowalski/skills) |
| `web-design-guidelines` | An audit of a finished page's code: accessibility, focus, reduced motion. Step 3 of `page-design`. | `designAudit.provider` = `web-design-guidelines` | any repo; installed for Claude Code; needs network on every run | [Vercel](https://github.com/vercel-labs/agent-skills) |
| `lavish` | [Review pages](/review-pages/): a plan, a decision or a grilling round opens as a page you annotate and answer. | `reviewPages.enabled` — on unless `false` | any repo, any machine; a session with no browser prints to the terminal | [Kun Chen](https://github.com/kunchenguid/lavish-axi) |

`cckit add` with no name prints this list for the repo you are in, each row marked `on` or `off`,
and says which ones do not apply here.

## Switch one on

<Steps>

1. **Choose it.** `cckit add <id>` asks one question and, on yes, sets that integration's config
   key in the project config. No other key changes and nothing is installed.

   ```bash
   cckit add            # list what can be added
   cckit add graft      # sets codeGraph.provider = graft
   ```

   An integration that cannot work in this repo is declined: exit 0, nothing written. In a repo of
   only `.sh` files, `cckit add graft` declines because Graft has no shell grammar.

2. **Install it.** `cckit doctor` prints one row per integration that is switched on. A missing
   tool is installed only after your yes for that run:

   ```bash
   cckit doctor         # in a terminal: asks, then installs on yes
   cckit doctor --fix   # installs without the prompt (alias --yes)
   ```

   With no terminal and no `--fix`, the doctor installs nothing, reports the tool missing and
   exits 1. A missing tool that is on only by default (`lavish`, with `reviewPages.enabled` unset)
   is a skip row instead: not installed even with `--fix`, and not a failure.

3. **Finish the step the doctor names.** After an install the doctor prints the one step it leaves
   to you: `mempalace mcp` for MemPalace, `graft init --agents claude --no-statusline --no-global`
   for Graft. mlx-lm and Lavish have none. For each of the three design skills: reload the agent
   session so it lists the skill, and commit the files the install wrote.

</Steps>

`KIT_DRY_RUN=1 cckit add <id>` writes nothing and prints the install candidates in order plus the
wire command.

## What your yes records

Your yes to an install is recorded as one line, `install:<id>`, in `.cckit/consent`. That file is
gitignored and shared by every worktree of the repo.

| Fact | Detail |
| --- | --- |
| What writes the line | `cckit doctor --fix`, a yes at the doctor's terminal prompt, or `bash scripts/lib/integration-install.sh --consent <id>`. |
| What it permits | The shared runner installing and wiring that one integration in that one repo. |
| What it does not permit | Any other integration, any other repo, or any other change cckit makes. |
| Without the line | The runner reports `no-consent` and runs nothing. `KIT_ASSUME_YES` is not consent. |
| To withdraw it | Delete the `install:<id>` line from `.cckit/consent`. |

`.cckit/consent` holds install consent only. It is not a general switch for cckit changing your
repo: see [the permission gate](/config-and-permissions/#the-permission-gate-ask-before-operating).

## How an install runs

`scripts/lib/integration-install.sh` is the one runner. For a missing tool with consent recorded,
it tries the descriptor's install candidates in the order written and skips one whose package
manager is not on `PATH`. The first candidate that exits 0 **and** leaves the tool detectable wins;
later candidates never run. If the tool is already detectable, nothing runs, so a second
`cckit doctor --fix` is a no-op.

| Integration | Candidates, in order | If no manager is present |
| --- | --- | --- |
| `mempalace` | `pipx install mempalace`, then `uv tool install mempalace` | `brew install pipx` |
| `mlx-lm` | `uv tool install mlx-lm`, then `pipx install mlx-lm` | `brew install uv` |
| `graft` | `npm install -g @nanonets/graft`, then `pnpm add -g @nanonets/graft` | nothing: the install fails |
| `impeccable` | `npx -y impeccable install --providers=claude --scope=project` | nothing: the install fails |
| `emil-design-eng` | `npx -y skills@latest add emilkowalski/skills --skill emil-design-eng -a claude-code -y` | nothing: the install fails |
| `web-design-guidelines` | `npx -y skills@latest add vercel-labs/agent-skills --skill web-design-guidelines -a claude-code -y` | nothing: the install fails |
| `lavish` | `npm install -g lavish-axi`, then `brew install node` — reached only when neither `lavish-axi` nor `npx` is on `PATH`, and only when the config sets `reviewPages.enabled: true` | nothing: the install fails |

Installing by hand with any of those commands works too: the doctor detects the tool and reports it
installed.

The full rule table, the descriptor fields and the doctor's exit codes are in the reference:
[Config & permissions → Integrations](/config-and-permissions/#integrations).

## The recipes are re-checked every month

A descriptor hardcodes facts its vendor can change: a package name, a flag, a binary's name.
`.github/workflows/integrations-check.yml` installs every descriptor for real on the 1st of each
month, on `ubuntu-latest` and `macos-15` (arm64), and opens an issue naming the integration and the
step that broke. Details: [the monthly recipe check](/config-and-permissions/#the-monthly-recipe-check).

## The tools, and who makes them

cckit wrote none of these tools. Each descriptor carries an `attribution` block, and the validator
refuses a descriptor without one.

### MemPalace

Persistent memory, scoped to one wing per project. Local, no API key. Setup and what the hooks do:
[Set up memory](/memory/).

<Aside type="note" title="Not affiliated">
MemPalace is independent open-source software by the [MemPalace](https://github.com/MemPalace/mempalace)
project. cckit is not a maintainer of it and has no affiliation with or endorsement from its
authors. Send MemPalace bugs to [its issue tracker](https://github.com/MemPalace/mempalace/issues).
</Aside>

### mlx-lm

The local model runtime behind cckit's local layer. Apple silicon only; on any other machine the
doctor prints a skip row and every caller falls back. The first server start downloads the
configured model, about 4.5 GB for the default. `local.port` and `local.model` are in the
[config reference](/config-and-permissions/#integrations).

<Aside type="note" title="Not affiliated">
mlx-lm is open-source software (MIT) from Apple's [ml-explore](https://github.com/ml-explore/mlx-lm)
project. cckit is not affiliated with Apple.
</Aside>

### Graft

Code-graph retrieval. `cckit add graft` also writes `.claude/rules/code-retrieval.md`, which routes
code questions to Graft verbs and falls back to Grep/Glob silently when the graph is absent. The
retrieval verbs parse with tree-sitter and call no model; `graft build --deep` is the one command
that calls an LLM, and cckit never runs it. Flags, files written and the hook-merge test:
[Code-graph retrieval: Graft](/config-and-permissions/#code-graph-retrieval-graft).

<Aside type="note" title="Not affiliated">
Graft is open-source software (MIT) by [NanoNets / Trail](https://github.com/trailhq/Trail-Code),
installed from its public npm package. cckit is not affiliated with either. Per the vendor README,
Graft makes a daily npm version check and one batched anonymous usage ping;
`graft telemetry disable` or `DO_NOT_TRACK=1` turns the ping off. cckit sets neither.
</Aside>

### Lavish

The page tool behind [review pages](/review-pages/). cckit runs it through `npx -y lavish-axi`, so
nothing stays installed, and no API key is read. `cckit add lavish` also writes
`.claude/rules/review-pages.md`; every profile already ships that rule. What opens a page, the
terminal fallback and where answers are written: [Review pages](/review-pages/).

<Aside type="note" title="Not affiliated">
Lavish (`lavish-axi`) is open-source software (MIT) by [Kun Chen](https://github.com/kunchenguid/lavish-axi),
run from its public npm package. cckit is not affiliated with its author and vendors none of its
code.
</Aside>

### The design skills

Three skills that [`page-design`](/skills/#page-design), cckit's own skill, applies in a fixed
order when a page is built. A skill is files, not a program: each descriptor detects its skill by
the file `.claude/skills/<id>/SKILL.md` in the project, or `~/.claude/skills/<id>/SKILL.md`, and
`verify` is the same file check. None needs an API key or a paid product. cckit copies none of
their content.

```bash
cckit add impeccable && cckit add emil-design-eng && cckit add web-design-guidelines
cckit doctor --fix
```

| Skill | Licence, and where it was read | What installing and running it does beyond writing files |
| --- | --- | --- |
| `impeccable` | Apache-2.0: the `LICENSE` file of [pbakaus/impeccable](https://github.com/pbakaus/impeccable) | Runs an engine binary that ships with the skill or is downloaded once into `~/.impeccable/bin/`. A new design fetches visual directions from the impeccable.style catalogue, with telemetry on or off. The installer can add a design hook that runs on every UI file the agent edits; in Claude Code that hook runs outside the model's permission checks. Its live mode can start the agent CLI with permission checks off: `page-design` never uses it in an unattended run. |
| `emil-design-eng` | MIT: the `LICENSE` file of [emilkowalski/skills](https://github.com/emilkowalski/skills) | Nothing stated by its author. It is one skill of a pack of 19; only this one is installed. |
| `web-design-guidelines` | MIT as stated in the README of [vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills), which holds no `LICENSE` file. The rules it fetches come from [vercel-labs/web-interface-guidelines](https://github.com/vercel-labs/web-interface-guidelines), which has an MIT `LICENSE` file | Fetches its rules from GitHub on every run: it does not work offline, and the rules can change between two runs. With no network `page-design` reports the audit as not run. |

All three were read on 2026-11-13.

**Where each installs.** Into the project, for Claude Code. `impeccable` is passed
`--scope=project --providers=claude`. The other two go through the third-party `skills` CLI
(`npx skills`, Node.js 22.20 or later), which installs into the current project unless given `-g`:
per its documentation, a copy under `.agents/skills/<id>/`, a link at `.claude/skills/<id>`, and an
entry in `skills-lock.json`. Commit what the install wrote. A Codex-only project is not covered:
the descriptors install and detect the Claude Code location only.

`page-design` itself is not an integration: it is cckit's own skill. `cckit add page-design` copies
it into an existing project and sets `tasks.design: true`; see [Skills](/skills/#page-design).

<Aside type="caution" title="Verified by one run">
One run is on record: on 2026-11-13 `cckit doctor --fix` installed all three in a Next.js project, with no terminal prompt. `impeccable` also wrote four `.claude/agents/impeccable-*.md` files, the `skills` CLI wrote `skills-lock.json`, and `.claude/settings.json` was not modified, so no design hook was added in that run. The doctor names
those extra files on the row of an install it has just made (the descriptor's `alsoWrites`), so
they are not first met in `git status`. Not recorded in that run: whether the `skills` CLI also
wrote a copy under `.agents/skills/`. Other versions of the installers are not covered. The pack's
own README documents only the whole-pack install; `--skill` is an option of the `skills` CLI. The
[monthly check](#the-recipes-are-re-checked-every-month) is what runs these commands. Installing
`impeccable` as a Claude Code plugin (`/plugin marketplace add pbakaus/impeccable`) works too, and
the doctor then still reports it missing, because a plugin leaves no file in `.claude/skills/`.
</Aside>

<Aside type="note" title="Not affiliated">
Impeccable is published by the GitHub account [pbakaus](https://github.com/pbakaus/impeccable),
`emil-design-eng` by [Emil Kowalski](https://github.com/emilkowalski/skills), and
`web-design-guidelines` by [Vercel](https://github.com/vercel-labs/agent-skills). cckit is not

## Add a tool of your own

Write `integrations/<id>.json` against `integrations/integration.schema.json`, then run
`bash scripts/lib/integrations.sh --validate`: it prints one `<id>: <field>: <problem>` line per
problem. The field list is in [Config & permissions → Integrations](/config-and-permissions/#integrations).
The steps, with a worked descriptor: [Add your own tool as an integration](/tutorials/add-your-own-integration/).

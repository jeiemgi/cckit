An agent session starts with no knowledge of the sessions before it. This guide connects
[MemPalace](https://github.com/MemPalace/mempalace), the memory tool cckit adopts, so each Claude
Code session in one project starts with that project's recent decisions and files its own work back
when it ends. [Why an agent team needs memory](/memory/) covers the reasons; this page is the setup.

**What you will have at the end:**

- memory switched on in the project config (`memory.enabled: true`);
- the `mempalace` command-line tool installed in its own isolated environment;
- the MemPalace MCP server connected to Claude Code;
- a session that opens with a short summary of the project, about 600 to 900 tokens.

Memory is off in every profile until you do this. It runs on your machine and needs no API key.

## Steps

### 1. Switch memory on in the project

Which command depends on where the project stands.

**The project is not set up yet.** Pass the flag to `cckit init`, or answer yes to the memory
question when you set up through the `/kit-init` command in Claude Code:

<Chat
  title="setting up the Bakery site with memory on"
  say="Set up the Bakery site with memory on."
  ran="cckit init --profile software --memory on"
  means="The result is four hook scripts under .claude/hooks/, registered in .claude/settings.local.json, the rule file .claude/rules/mempalace.md, and the project's summary header, .claude/mempal-identity.<wing>.txt. A wing is MemPalace's name for one project's memory; <wing> is the project's short name."
>
  Done. The memory hooks, the rule and the summary header are in the project, and `memory.enabled`
  is on. The tool itself comes in the next step.
</Chat>

**You already ran `cckit init` without memory.** cckit has no command that adds only the memory
files. `cckit init` stops on a project that is already set up unless you pass `--force`, which
writes cckit's generated files again, the memory files included. Commit your work first, run it
with the profile the project uses, and read the diff afterwards:

<Chat
  title="adding memory to a Bakery site that was set up without it"
  say="The Bakery site has no memory yet. Add it, and show me the diff afterwards."
  ran="cckit init --profile <profile> --memory on --no-github --force"
  means="Commit your work first. cckit init --upgrade does not add the memory files, and cckit add mempalace only sets memory.enabled in a project that already has them."
>
  The memory files are written again alongside cckit's other generated files. Read the diff before
  you commit it.
</Chat>

### 2. Let `cckit doctor` install the tool

<Chat
  title="installing the memory tool for the Bakery site"
  say="Check the memory setup of the Bakery site, and install the tool if it is missing. Ask me first."
  ran="cckit doctor"
  means="The doctor sees that memory is on and asks before it installs anything. On your yes (or with --fix) it installs the MemPalace command-line tool into an isolated environment: pipx first, uv if pipx is not there."
>
  I asked, you said yes, and the tool is installed. The same run created the summary header, which
  was missing, and refreshed an out-of-date session-start hook.
</Chat>

To install by hand, run `pipx install mempalace`, the first command the descriptor tries. The
doctor then finds the tool and reports it installed. The commands live in
`integrations/mempalace.json`; MemPalace is one of the [integrations](/integrations/) cckit
installs this way.

### 3. Connect the MCP server

<Chat
  title="connecting memory search to the agent"
  say="Connect memory search, so you can look things up during a session."
  ran="mempalace mcp"
  means="The hooks cover the start and the end of a session. Searching and saving during a session go through MemPalace's MCP server: the connection Claude Code uses to call a tool while it works. This command prints the line that registers it."
>
  That printed the line that registers the server with Claude Code. Run it, then restart Claude
  Code.
</Chat>

### 4. Describe the project in the header

<Chat
  title="describing the Bakery site in its memory header"
  say="Describe the Bakery site in its memory header: Next.js, a neighbourhood bakery, prices in euros."
  ran="cat .claude/mempal-identity.<wing>.txt"
  means="This header is shown at the start of every session in this project. The line to edit is the Stack: line."
>
  I edited the `Stack:` line and read the file back. Every session in this project now opens with
  that description.
</Chat>

## Check that it worked

1. Run `cckit doctor`. The Integrations section reports the `mempalace` CLI as installed, and the
   **Memory (MemPalace)** section reports the identity header as wing-scoped and the session-start
   hook as current.
2. Start a new Claude Code session in the project. Its context opens with the header you edited,
   followed by recent entries from this project's wing. A project with nothing filed yet shows the
   header alone.
3. Finish a session, start another, and ask about something the first one decided. The rule file
   tells the agent to search memory before it answers, so the answer should cite the earlier
   session.

Every session after this loads the header and the project's recent decisions. The rule file
`.claude/rules/mempalace.md` tells the agent when to read and when to write, so you do not have to
say "remember this". [How cckit uses memory](/memory/how-cckit-uses-it/) describes each hook and
where each kind of note goes.

<Aside type="tip" title="Built on MemPalace">
The memory engine, the palace format and the MCP server are the work of the open-source
[MemPalace](https://github.com/MemPalace/mempalace) project. cckit adds the hooks and the per-wing
header; MemPalace does the remembering. cckit is not affiliated with the project. Send MemPalace
bugs to its own issue tracker.
</Aside>

## Troubleshooting

**`doctor` did not install MemPalace.** It installs it only when memory is on. Switch it on as in
step 1, then run `cckit doctor`. With no terminal attached it installs
nothing unless you pass `--fix`.

**Your agent is not recalling anything.** Confirm the MCP server line from `mempalace mcp` is registered
with Claude Code, and that `.claude/rules/mempalace.md` exists. That rule is what tells the agent to
search memory before it answers.

**Memories from another repository showed up.** Memory is scoped per wing, one per project. Check
that you are in the right repository and that `memory.wing` in the project config is not shared
with another project.

**You use Codex.** `cckit init --adapter codex` installs no memory hook, even with `--memory on`.
See [Under Codex](/memory/how-cckit-uses-it/#under-codex).

Some work has a clear finish line and no need for conversation: make the failing tests pass,
clear the lint errors, finish a migration. Leaving an agent alone on it raises one worry. An
agent that decides for itself when it is done can stop early, or never stop.

`cckit autopilot run` takes that decision away from the agent. It starts the agent with no
terminal (`claude -p` or `codex exec`), one round at a time. After every round, code decides
whether another round starts: a command you chose passed, or a limit you set was reached. Nothing
the agent says ends or extends the run, and the run never merges and never closes an issue.

Each step starts with what you say to your agent in the chat. Below it is the command your agent
runs. The example is the Bakery site: the `/menu` page has to build and lint clean.

**What you will have at the end:** a branch where your completion check passes, optionally with
its pull request open, or a stopped run whose exit code tells you which limit ended it.

## Steps

### 1. Start the issue and enter its worktree

A run works on the current branch and refuses the base branch.

<Chat
  title="starting the menu page issue before an unattended run"
  say="Start the menu page issue and work in its worktree."
  ran={['cckit start <issue>', 'cd <the worktree path it prints>']}
  means="The run needs a branch of its own, because it refuses the base branch."
>
  The menu page issue has its own worktree and branch. I am working in it now.
</Chat>

### 2. Choose the completion check

It is a command that exits 0 when the objective is met: the test command, a linter, a script of your
own. Run it once by hand. It should fail now, for the reason the objective describes. For the
Bakery site it is `pnpm build && pnpm lint`, the check the recipe sets.

### 3. Print the plan

A dry run starts nothing and writes nothing.

<Chat
  title="previewing the unattended run on the menu page"
  say="Show me what an unattended run would do to make the menu page build and lint clean. Do not start anything."
  ran={'cckit autopilot run --objective "make the menu page build and lint clean" --until "pnpm build && pnpm lint" --max-iters 3 --dry-run'}
  output={[
    "…",
    "  agent   : 'claude' -p --output-format json   < prompt on stdin",
    "  limits  : max-iters 3 · max-seconds 3600 · round-seconds 900 · max-tokens none",
    "  until   : pnpm build && pnpm lint",
    "…",
  ]}
  means="You see the branch and issue, the agent command, the limits, the completion check and the state file path before anything starts."
>
  This is the plan: the agent runs headless, at most 3 rounds, and the run ends when the build and the
  lint pass. Nothing was started and nothing was written.
</Chat>

### 4. Give the agent permission to edit

cckit adds no permission flag. A run that must change files names its own, one `--agent-arg` per word.

<Chat
  title="letting the unattended run edit files"
  say="Let the run edit files, then show me the exact command it would start."
  ran={'cckit autopilot run --objective "make the menu page build and lint clean" --until "pnpm build && pnpm lint" --max-iters 3 --agent-arg --permission-mode --agent-arg acceptEdits --dry-run'}
  means="Read the agent line of the dry run: it is the exact command that will start."
>
  I added the permission flag for editing and ran the preview again. The agent line now shows the
  command that will start. Nothing ran.
</Chat>

For Codex, name the agent and its sandbox instead:

```bash frame="terminal"
--agent codex --agent-arg -s --agent-arg workspace-write
```

### 5. Run it

Drop `--dry-run`. Add a token ceiling, a gate and the PR step when you want them.

<Chat
  title="running the menu page objective unattended"
  say="Run it for real: stop after 5 rounds, 30 minutes or 400000 tokens, run the full gate at the end, and open the pull request if it passes."
  ran={'cckit autopilot run --objective "make the menu page build and lint clean" --until "pnpm build && pnpm lint" --check "pnpm build && pnpm lint" --max-iters 5 --max-seconds 1800 --max-tokens 400000 --agent-arg --permission-mode --agent-arg acceptEdits --publish --summary "<one-line summary>"'}
  output={[
    "…",
    "autopilot run: round 1 (bound 900s)",
    "autopilot run: stopped - reason=done rounds=1 elapsed=62s tokens=421592 (the agent exited 0 after round 1)",
    "…",
  ]}
  means="`--check` runs once after the completion check passes; if it fails, nothing is published. `--publish` then opens the pull request with `cckit pr`, unless the branch already has one."
>
  The run stopped with reason done after one round. The completion check passes. The pull request is
  the next step; I did not merge anything, a run never merges.
</Chat>

### 6. Read how it ended

The exit code is the stop reason.

<Outcomes of="cckit autopilot run">

| Exit | Stop reason | What to do |
| --- | --- | --- |
| `0` | `done` | The completion check passed, and the gate when given. Review the branch or the PR. |
| `3` | `agent-failed` | The agent exited non-zero. Read its output, fix the cause. |
| `4` | `limit-iters`, `limit-seconds`, `limit-tokens`, `usage-unknown` | A limit was reached. Resume with a higher one, or stop. |
| `5` | `no-progress` | A round changed neither `HEAD` nor the working tree. Rewrite the objective. |
| `6` | `check-failed` | The gate failed. Nothing was published. |
| `7` | `publish-failed` | The work passed and `cckit pr` did not open the PR. Run it by hand. |
| `130` | `interrupted` | A signal killed the run or the agent. |
| `2` | *(refusal)* | A bad flag, the base branch, an unsupported agent, or a run already live on this branch. Nothing was written. |

</Outcomes>

### 7. Resume a stopped run

Round, time and token counts carry over, so raise the limit that stopped it.

<Chat
  title="continuing a run that hit its round limit"
  say="The run stopped at its round limit. Continue it with up to 8 rounds."
  ran="cckit autopilot run --resume --max-iters 8"
  means="Counts carry over. To discard the state and start over, use the fresh form below."
>
  I resumed the stopped run with the higher limit. The earlier rounds still count.
</Chat>

```bash frame="terminal"
cckit autopilot run --fresh --objective "<text>" --until "<cmd>"   # discard the state, start over
```

## Check it worked

The exit code is `0` and the stop reason is `done`. Run your completion check by hand in the
worktree: it passes now, where it failed in step 2. The state file under `.cckit/autopilot/`
records the reason, the round count and the usage.

## How it works

The state of a run is one JSON file per branch under `.cckit/autopilot/`, written at every stop
with the reason, the round count, the elapsed seconds, the usage and the resume command. The
directory sits at the root of the repo and is shared by every worktree. `cckit init` adds
`.cckit/` to `.gitignore`. In a project scaffolded before it did, `git check-ignore .cckit/`
prints nothing: add the line `.cckit/` yourself.

Without `--until`, the run ends when the agent exits 0 after a round that changed something. With
it, the command's exit code is the only thing that ends the run as `done`.

`--until` is also asked before round 1. A command that already passes there, such as a build on a
project that builds today, ends the run with exit 0, `rounds=0` and nothing changed; stderr says
so. `--until` is the stop condition, not a gate: to require that the finished work passes a
command, use `--check "<cmd>"`.

Two limits behave differently from the others:

- **Tokens are checked between rounds**, from the usage the agent CLI prints. A round in flight is
  not cut off by tokens, so one round can pass the ceiling by its own size. Bound a single round
  with `--round-seconds`. A round that prints no usage stops the run with `usage-unknown`.
- **There is no cost limit.** Codex prints no cost and cckit applies no price list.

Which limits are enforced, partly enforced or unsupported, with the test behind each:
[Unattended run limits](/agent-compatibility/#unattended-run-limits). Every flag is printed by
`cckit autopilot run --help`; the verb's row is in the [CLI reference](/cli-reference/).

<Aside type="caution" title="Tested with stub agents">
The limits are tested by stopping a stub agent in `scripts/autopilot-run-test.sh`. The reference
page states that no limit has been run against a live agent. Start with a low `--max-iters` and
a short `--max-seconds` on a branch you can discard.
</Aside>

## Troubleshooting

**`an objective is required` and exit 2.** A new run needs `--objective "<text>"` or
`--prompt-file <f>`.

**`nothing to resume` and exit 2.** No stopped run is recorded for this branch. Start one without
`--resume`.

**The run stops after one round with `no-progress`.** The agent could not edit files. Add the
permission flags from step 4 and check the `agent` line of a dry run.

**The run stops with `usage-unknown`.** `--max-tokens` is set and a round printed no usage, so the
ceiling could not be read. Remove `--max-tokens` and bound the run with `--max-iters` and
`--max-seconds`.

**A start is refused because an earlier agent is still alive.** A previous run's agent process is
still running on this branch. Wait for it to exit, or stop that process yourself, then resume.

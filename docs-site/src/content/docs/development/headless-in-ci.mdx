A CI job or a scheduled run has nobody to read a nicely formatted table. An agent in that job
that reads output meant for people has to guess at columns and wording, and guesses break when
the wording changes.

cckit gives every verb a second output for this case. Add `--llm` and a verb that reports state
prints data: JSON for a single result, TOON (a compact table format) for a list. The agent reads
the board, the stack and the plan as data, picks the highest-priority unblocked issue and drives
it.

**What you will have at the end:** an agent in a job with no person attached that reads the
board as data and works one issue through, with small hand-offs to any sub-agent it starts.

## Steps

<Steps>

1. **Prime the headless agent.** Tell it there's no human and to consume data, not prose.

   <div class="cckit-prompt">

   ```text frame="terminal" title="Prompt to paste"
   You're running headless — no human watching. Work the board through to merged on your own: read
   state as structured data, pick the highest-priority unblocked issue, and drive it start to finish.
   Keep token use lean when you hand context to sub-agents.
   ```

   </div>

2. **Consume every verb as data.**

   ```bash frame="terminal"
   cckit sync --llm          # board state + what's unblocked, as TOON
   cckit scan --llm          # repo stack + kit state, as JSON
   cckit plan --llm          # the session-fit wave plan, as TOON
   ```

3. **Compact context for sub-agents.** Pipe uniform arrays through `encode-context` so hand-offs stay
   token-lean:

   ```bash frame="terminal"
   echo "$json" | cckit encode-context   # compact uniform arrays into TOON for sub-agents
   ```

</Steps>

## Check it worked

Run one verb in the job and parse it:

```bash frame="terminal"
cckit scan --llm | jq .     # exits 0 and prints one JSON object
```

In the job log, the agent's commands carry `--llm` and none of its decisions quote a
human-formatted table.

## How it works

Every verb accepts `--llm`, each verb that produces a result prints it as JSON or TOON, and the repo
ships an [`AGENTS.md`](/agents/) contract, so an agent reasons over structured data instead of scraping human
output. Point the agent at `AGENTS.md` once and it knows the grammar; `--llm` then gives it the board,
the stack, and the plan as JSON/TOON it can act on without a human in the loop.

<Aside type="note" title="TOON keeps hand-offs cheap">
`encode-context` compacts uniform arrays into TOON — a denser encoding than raw JSON — so passing
context to sub-agents costs fewer tokens.
</Aside>

## Troubleshooting

**A verb printed human output in CI.** Add `--llm`. Every verb accepts it; if one still prints prose,
you've hit a verb with no JSON result (`init`, `orchestrate`, `autopilot`, `brief`) — that's expected.

**The agent doesn't know the verbs.** It hasn't read the contract. Have it read `AGENTS.md` and
`cckit.config.json` once at the start of the run.

**Hand-offs are burning tokens.** Pipe the JSON through `cckit encode-context` before handing it to a
sub-agent; TOON is smaller than the equivalent JSON.

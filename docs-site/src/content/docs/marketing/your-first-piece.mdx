Describe a piece, get a link, approve it. The example is the landing page of Pilot Light Bakery.

<Steps>

1. **Describe the piece.**

   <Chat
     title="handing over the Pilot Light Bakery landing page"
     say="I need a landing page for my bakery, Pilot Light. At the top the name and a short line about us, then three breads with prices, our opening hours and a contact form. Can you build it?"
     means="Nothing is public yet."
   >
     I wrote it down as a task and started building. I will tell you when there is a link.
   </Chat>

   <Outcomes title="For the technical person: the two commands behind this step">

   ```text
   cckit task new "<title of the piece>" --body "<what goes on the page>"
   cckit task run <id>
   ```

   `cckit task new` prints the task's id, and `<id>` is that id. The notes after `--body` are the
   paragraph about what goes on the page.

   </Outcomes>

2. **Wait for the link.** It arrives once the site passes its check.

   <Outcomes title="How long it takes, and when no link comes">

   - One round of a landing page like this one took under three minutes in a real run with nobody
     stepping in; a second page, a menu, took about one minute.
   - With the design skills on [The tools we plug in](/marketing/tools/#design-skills-how-a-page-is-designed),
     your assistant writes a short design brief first and the review names the skills it loaded. In
     the one run on record that took about seven minutes.
   - When the check fails, or when nothing changed, no review is opened and your assistant says why.

   </Outcomes>

3. **Read it. Ask for changes in plain words.**

   <Chat
     title="asking for changes on the Pilot Light Bakery landing page"
     say="The line at the top is too long. Use 'Bread baked this morning'. And add a photo of the shop."
     means="The review link stays the same."
   >
     The line at the top is changed and the review is updated. I could not add a photo: there is
     none in the project. Send me one and I will add it.
   </Chat>

4. **Approve.** A colleague opens the link and clicks **Approve**. Then tell your assistant, and it marks the piece done.

   <Outcomes title="If you work alone, and what approving does">

   - GitHub does not let the person who asked for a review approve it. If you work alone, read the
     review yourself and finish it: tell your assistant the page is fine, or use the green
     **Merge pull request** button on the review page.
   - Once approved, the page becomes part of the shared version and the task is marked done. See
     [After approval](/marketing/review-and-approval/#after-approval) and
     [Review and approval](/marketing/review-and-approval/).
   - You never edit code, and nothing is approved by itself.

   </Outcomes>

</Steps>

<Aside type="note" title="Approved is not published">
cckit stops at approved. [Put an approved piece online](/marketing/go-live/) says what to hand the person who publishes.
</Aside>

## Coming back to a piece

  Nothing is waiting for a review. Do you want to continue the post?
</Chat>

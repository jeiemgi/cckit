The first time, hand over something small and complete: one landing page, one post, one section
of a site. You describe it, cckit builds it in the background and returns a review link, and you
approve it.

**Who does it:** you describe and approve. Claude and its assistants build.

**What you will have at the end:** the piece as an approved version in the project, and the task
marked done.

**Before you start:** the [keys are given](/marketing/get-set-up/) and the project is open in
Claude Code.

## Option 1: hand it over

<Steps>

1. **Describe the piece in one paragraph.** Say what it is and what goes on it. Claude records
   it as a task:

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   Record a new task: a landing page for a bakery. A hero with the name and a tagline, three products with prices, opening hours, and a contact form. Then run it.
   ```

   </div>

   Claude runs two commands for you. If you prefer to type them, they are:

   ```text
   cckit task new "A landing page for a bakery" --body "<what goes on the page>"
   cckit task run <id>
   ```

   `cckit task new` prints the task's id, and `<id>` is that id. The notes after `--body` are the
   paragraph about what goes on the page.

2. **Wait for the link.** One unattended round of a landing page like this one took under three
   minutes in a real run; a second page, a menu, took about one minute. The project's check
   passes before the review is opened. When the check fails, or when nothing changed, no review is
   opened and the run says why.

3. **Look at the result and approve.** Open the review link. See
   [Review and approval](/marketing/review-and-approval/) for what the page shows. If you want
   changes, say so:

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   Read the review comments on this task and apply them. Tell me which ones you did not apply and why.
   ```

   </div>

4. **Approved.** Approving and merging the review marks the task done:

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   The review is approved. Finish this piece.
   ```

   </div>

</Steps>

{/* VERIFY-504 */}
For a page, Claude loads the design skills described on [The tools we plug in](/marketing/tools/#design-skills-how-a-page-is-designed)
and writes a short design brief before it builds. The review says which design skills were loaded
in that run.

You never edit code. Nothing merges by itself, and cckit does not publish: the result is an
approved site that builds, and putting it on a public address is a separate step.

## Option 2: write it together

Use this for a piece you want to shape sentence by sentence, such as a blog post. You work with
Claude and its editor assistant in a draft of your own, and the approved version does not change
until the piece is approved.

<Steps>

1. **Tell Claude what you want to make and start the draft.**

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   I want to write a blog post announcing our spring workshop. Record it as a new piece of work and start a draft for it.
   ```

   </div>

2. **Agree on an outline.**

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   Propose an outline for this post. The reader is a small-business owner who has not heard of us. The one thing I want them to do is sign up for the workshop.
   ```

   </div>

   Change it until it is right: what to cut, what to move, what is missing.

3. **Write the draft.**

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   Write the first draft from that outline. Follow our brand voice.
   ```

   </div>

   Claude writes the post as a file in the project and tells you where it is. Edit it together:
   "make the opening shorter", "this paragraph sounds like an ad", "add the date and the price".
   If your team has [set its brand voice](/marketing/brand-voice/), Claude reads it first.

4. **Ask for a review.**

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   This is ready. Save it and ask for a review.
   ```

   </div>

   Claude saves the draft, sends it to GitHub and gives you a link.

5. **A teammate reviews it, and you apply the changes.** Send the link to the person who
   approves. GitHub does not let the person who asked for the review approve it, so the approver
   is someone else. Then:

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   Read the review comments on this post and apply them. Tell me which ones you did not apply and why.
   ```

   </div>

6. **Approved.** Once the review says approved:

   <div class="cckit-prompt">

   ```text title="Say this in the chat"
   The review is approved. Finish this piece.
   ```

   </div>

   Claude makes the approved draft part of the shared version, marks the piece done and tidies up
   the draft. The approver can also finish it from the review page with the green
   **Merge pull request** button (some projects label it **Squash and merge**).

</Steps>

## Check that it worked

Ask Claude "Where are we?". The piece is no longer listed as in progress or waiting for a review,
and it counts as done.

## Coming back to a piece

Drafts survive closing the app. Open the project again and say:

<div class="cckit-prompt">

```text title="Say this in the chat"
Where are we? Show me my drafts and anything waiting for a review.
```

</div>

Then say which one to continue. To pick new work instead, say: "Show me what is ready and I will
pick."

<Aside type="note" title="Approved is not published">
cckit stops at approved. See [after approval](/marketing/review-and-approval/#after-approval).
</Aside>

Sooner or later a developer tells you "I opened a PR", or a button on GitHub says "Merge", and
you need to know whether that concerns you. This page is for that moment.

cckit was built for software teams, and its tools use their words. With the marketing profile
your assistant speaks in plain language, but the developer words still appear on GitHub, in messages from
developers and when you ask your assistant for detail. This page maps each one to the word you already
use.

You do not need to learn them to do your work.

## The four you will meet first

<div class="cckit-nowrap-2">

| Plain word | Developer word | What it is |
| --- | --- | --- |
| **Draft** | **branch** | A separate line of changes for one piece of work. What you write in it stays apart from the shared version until it is approved. More: [How one change is built](/development/) |
| **Review** | **pull request**, **PR** | The page on GitHub where a draft is read, commented on and approved. "Open a PR" means "ask for a review". More: [Take an issue to merged](/development/issue-to-merged-pr/) |
| **Piece of work**, **task** | **issue**, **light task** | The record of one thing to make: a title, a description and whether it is open or closed. An issue is that record on GitHub. A light task is the same record as a file in the project's `tasks/` folder, which is where the marketing setup keeps it. More: [How one change is built](/development/) · [Tasks without GitHub issues](/project-management/light-tasks/) |
| **Approved** | **merged** | The draft's changes are part of the shared version. To "merge" is to finish an approved piece. More: [Why merging is a decision](/ship/) |

</div>

## The rest

<div class="cckit-nowrap-2">

| Plain word | Developer word | What it is |
| --- | --- | --- |
| Project | repository, repo | The folder that holds your content and its whole history, kept on GitHub. More: [What you set up, and why](/getting-started/) |
| The shared version | base branch, `main`, `develop` | The version everyone agrees on. Drafts start from it and return to it. More: [How one change is built](/development/) |
| A draft's own folder | worktree | A separate folder on your computer for one draft, so two drafts never mix. Your assistant creates and removes it. More: [How one change is built](/development/) |
| Saved change | commit | One saved step in a draft, with a note saying what changed. More: [How one change is built](/development/) |
| Send to GitHub | push | Copy your saved changes from your computer to GitHub so others can see them. More: [How one change is built](/development/) |
| Campaign | effort | Several pieces of work under one plan. "Effort" is the name when the task list is on GitHub; its pieces are then approved together. More: [Break a feature into an effort](/project-management/break-a-feature-into-an-effort/) |
| A piece in a campaign | sub-issue | One entry under the campaign's entry, when the task list is on GitHub. More: [Efforts and waves in practice](/project-management/efforts-and-waves/) |
| Tag | label | A colored tag on a piece of work: its kind, its priority, who it is for. More: [Config and permissions](/config-and-permissions/) |
| Stage | milestone | A named stage a piece of work belongs to, such as Draft or Review. More: [Config and permissions](/config-and-permissions/) |
| The keys | setup, sign-in, credentials | The accounts and the project a technical person sets up once so cckit can work for you: Claude Code, a GitHub account and the project. More: [Install and check](/getting-started/install/) |
| Memory | MemPalace | An optional tool that lets the project remember decisions between sessions. Off by default. More: [Why an agent team needs memory](/memory/) |
| Setup | profile | The set of skills, roles and rules installed for a kind of team. Yours is the marketing profile. More: [Initialize a project](/getting-started/initialize/) |
| A method your assistant follows | skill | A written method your assistant follows for one job, such as writing copy or planning a campaign. More: [Skills cckit ships](/skills/) |
| Assistant | agent, sub-agent | A role your assistant takes on for part of the work: planner, editor, designer, researcher. More: [Who does what](/marketing/who-does-what/) |
| Automatic check | hook, gate | Something that runs by itself before a change is saved or approved, such as a check for passwords left in a file. More: [Hooks](/hooks/) |
| Typed command | CLI, terminal | The text window developers type commands into. The technical person uses it during setup. More: [CLI reference](/cli-reference/) |

</div>

## Sentences, translated

| You hear | It means |
| --- | --- |
| "I opened a PR for the spring post." | "The spring post is ready for review. Here is the link." |
| "Can you review my PR?" | "Please read my draft and approve it or tell me what to change." |
| "It's merged." | "It is approved and part of the content now." |
| "It's on a branch." | "It is still a draft." |
| "There's a conflict." | "Two drafts changed the same lines. Ask your assistant to sort it out, and read what it proposes." |
| "CI is red." | "An automatic check failed. Ask your assistant what failed and whether it can fix it." |

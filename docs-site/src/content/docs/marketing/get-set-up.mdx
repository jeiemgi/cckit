"The keys" are the accounts and the project that cckit needs in order to work for you: Claude
Code, a GitHub account and the project itself. You give them once. After that, cckit handles
the process behind each piece.

The example on these pages is one shop: Pilot Light Bakery, a neighbourhood bakery on Alder Row.
Its owner sells bread and pastries, has never opened a terminal, and works with one colleague at
the counter, who reads and approves what goes on the site. Their project is called the Bakery
site.

The setup is done once and it needs a terminal. That is why a technical person does it: a
developer on your team, an agency contact or a freelancer, for about half an hour. After it,
nobody on the team needs a terminal again.

**What you will have at the end:** a project you can open in Claude Code, where your assistant
speaks in plain language, knows the four assistants and answers "Where are we?".

What each connected tool does for you is on [The tools we plug in](/marketing/tools/).

## The keys

- **Claude Code** on your computer. The desktop app is enough.
- **A GitHub account** for each person who writes or approves, with access to the project. An
  approver needs only a browser.
- **The project.** For a new website, the setup creates it. For an existing project, it adds to
  it.

## Part 1: for the technical person

This part uses a terminal. If that is not you, send this section to the person who will do it.

<Outcomes title="For the technical person: install cckit and create the project">

1. **Install cckit and sign in to GitHub** on the marketer's computer:
   [Install and check](/getting-started/install/).

2. **Create the project with the marketing profile.** For a new website:

   ```text
   cckit init <folder> --profile marketing --recipe nextjs-shadcn --yes
   ```

   In a real run this one command created a working Next.js and shadcn project, a private GitHub
   repository, and the labels and settings, after one confirmation. For a project that already
   exists, run `cckit init --profile marketing` inside it, or `/kit-init marketing` in Claude
   Code. What it installs, and what to do if a part did not run, is in the
   [cckit init reference](/init-reference/#the-marketing-profile).

3. **Give every writer and approver access** to the project on GitHub, and decide who approves.
   A setup where one person asks for work and another approves works from day one.

**A private repository on a free GitHub plan.** Protection of the shared version is not available
on a private repository on a free GitHub plan. The setup says so when it skips that step. The
project works without it.

</Outcomes>

<Outcomes title="For the technical person: what runs when they say it">

<div data-table="grid">

| What they say | What runs |
| --- | --- |
| "Where are we?" | `cckit status` |
| "Show me what I have started and anything waiting for a review." | `cckit task list` |
| "What is next?" | `cckit task next` |
| "I need a landing page for …" | `cckit task new "<title>" --body "<what goes on the page>"`, then `cckit task run <id>` |
| "Let's start the draft." | `cckit task start <id>` |
| "Save it and ask for a review." | `cckit task finish <id> "<summary>" --all` |
| "It is approved. Can you wrap it up?" | `cckit merge <pr>` |
| "I want to plan a campaign." | the campaign skill; the plan opens with `cckit page open <html-file>` and the answer is saved with `cckit page answer` |

</div>

Reading review comments and editing a draft are done by the assistant itself, not by a `cckit`
verb. The full verb list is in the [CLI reference](/cli-reference/).

</Outcomes>

## Part 2: for you, and the check that it worked

<Steps>

1. **Open the project in your assistant's app.** The technical person shows you where it is the
   first time.

2. **Ask where things stand.** On a new project the list is short or empty.

   <Chat
     title="asking where things stand on the new Bakery site"
     say="Where are we?"
     means="An answer means the setup works."
   >
     The Bakery site is set up. Nothing is in progress and nothing is waiting for a review.
   </Chat>

3. **Ask what you can hand over.**

   <Chat
     title="asking what can be handed over for the bakery"
     say="What can I ask you to do here?"
     means="You do not need the list by heart. Ask again whenever you are unsure."
   >
     You can hand me a page, a post or a whole campaign for the bakery. Describe it in plain words.
     I write it down, build it in the background and give you a link to review. You approve it or ask
     for changes. I do not put anything online.
   </Chat>

</Steps>

## If something is off

| What you see | What to do |
| --- | --- |
| Your assistant says it cannot reach GitHub, or asks you to sign in | Ask the technical person to redo step 1 of Part 1. |
| Your assistant says it cannot start a draft | Part of the setup did not run. Send the technical person [this link](/init-reference/#the-marketing-profile). |
| Your assistant does not know the roles, the brand voice or the plain-language mode | The same cause. Send the technical person [the same link](/init-reference/#the-marketing-profile), then try again. |
| Your assistant answers with developer terms you do not know | Say "Explain that in plain language." The words are on [Words you will hear](/marketing/words-you-will-hear/). |
| Your assistant asks permission to run something | Read what it says it will do. Creating a draft, saving your work and asking for a review are expected. If you are unsure, say no and ask it to explain. |

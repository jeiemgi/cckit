"The keys" are the accounts and the project that cckit needs in order to work for you: Claude
Code, a GitHub account and the project itself. You give them once. After that, cckit handles
the process behind each piece.

There is setup, and it takes a terminal. That is why a technical person does it: a developer on
your team, an agency contact or a freelancer, for about half an hour. After it, nobody on the team
needs a terminal again.

**What you will have at the end:** a project you can open in Claude Code, where Claude speaks in
plain language, knows the four assistants and answers "Where are we?".

What each connected tool does for you is on [The tools we plug in](/marketing/tools/).

## The keys

- **Claude Code** on your computer. The desktop app is enough.
- **A GitHub account** for each person who writes or approves, with access to the project. An
  approver needs only a browser.
- **The project.** For a new website, the setup creates it. For an existing project, it adds to
  it.

## Part 1: for the technical person

This part uses a terminal. If that is not you, send this section to the person who will do it.

<Steps>

1. **Install cckit and sign in to GitHub** on the marketer's computer:
   [Install and check](/getting-started/install/).

2. **Create the project with the marketing profile.** For a new website:

   ```text
   cckit init <folder> --profile marketing --recipe nextjs-shadcn --yes
   ```

   In a real run this one command created a working Next.js and shadcn project, a private GitHub
   repository, and the labels and settings, after one confirmation. For a project that already
   exists, run `cckit init --profile marketing` inside it, or `/kit-init marketing` in Claude
   Code. What it installs, and what to do if a part did not run, is in the
   [cckit init reference](/init-reference/#the-marketing-profile).

3. **Give every writer and approver access** to the project on GitHub, and decide who approves.
   A setup where one person asks for work and another approves works from day one.

</Steps>

<Aside type="caution" title="A private repository on a free GitHub plan">
Protection of the main line is not available on a private repository on a free GitHub plan. The
setup says so when it skips that step. The project works without it.
</Aside>

## Part 2: for you, and the check that it worked

<Steps>

1. **Open the project in Claude Code.** The technical person shows you where it is the first time.

2. **Ask Claude where things stand:**

   ```text
   Where are we?
   ```

   Claude answers with what is in progress, what is waiting for a review and what needs cleaning
   up. On a new project the list is short or empty. An answer means the setup works.

3. **Ask what you can hand over:**

   ```text
   I am on the marketing team and I do not use developer tools. What can I hand over to you in this project?
   ```

</Steps>

## If something is off

| What you see | What to do |
| --- | --- |
| Claude says it cannot reach GitHub, or asks you to sign in | Ask the technical person to redo step 1 of Part 1. |
| Claude says it cannot start a draft | Part of the setup did not run. Send the technical person [this link](/init-reference/#the-marketing-profile). |
| Claude does not know the roles, the brand voice or the plain-language mode | The same cause. Send the technical person [the same link](/init-reference/#the-marketing-profile), then try again. |
| Claude answers with developer terms you do not know | Say "Explain that in plain language." The words are on [Words you will hear](/marketing/words-you-will-hear/). |
| Claude asks permission to run something | Read what it says it will do. Creating a draft, saving your work and asking for a review are expected. If you are unsure, say no and ask it to explain. |

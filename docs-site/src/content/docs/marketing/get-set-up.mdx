Setup happens once per project. It has two parts: a part for someone technical, and a part for you.

## What you need

- **A project on GitHub** where your content lives or will live. cckit starts from a project that
  already exists; it does not create a website.
- **A GitHub account** for each person who writes or approves, with access to that project.
- **Claude Code** on your computer. The desktop app is enough.
- **Someone technical for about half an hour**: a developer on your team, an agency contact, a
  freelancer.

## Part 1: for the technical person

This part uses a terminal. If that is not you, send this section to the person who will do it.

<Steps>

1. **Install cckit and sign in to GitHub** on the marketer's computer:
   [Install cckit](/getting-started/install/), then [Check your platform](/getting-started/install/).

2. **Open the project in Claude Code and run the setup with the marketing profile:**

   ```text
   /kit-init marketing
   ```

   The marketing profile installs the writing, brand voice and campaign skills, the four roles
   (planner, editor, designer, researcher) and the plain-language mode, in which Claude says
   "draft", "review" and "approve" and keeps developer terms out of the conversation unless asked.
   From a terminal the same setup is `cckit init --profile marketing`. What the setup writes and
   asks is on [Initialize cckit](/getting-started/initialize/).

   The setup lists its git and GitHub steps and asks once before running them. Say yes. Those
   steps save the setup files into the shared version every draft starts from and send them to
   GitHub, so each new draft and each teammate's copy of the project has them. On a project that
   is new on GitHub they also create that shared version, named `develop`; a project that is
   already on GitHub keeps the one it has.

   If the last lines of the output say `Git and GitHub setup: not run`, run `cckit init --yes` in
   the project folder. The lines after it name what was left undone. Until that has run, a new
   draft starts without the setup files, and Claude works in it without the team's rules.

3. **Give every writer and approver access** to the project on GitHub.

</Steps>

<Aside type="tip" title="Approvals">
Decide now who approves. A setup where one person writes and another approves works from day one.
</Aside>

## Part 2: for you

<Steps>

1. **Open the project in Claude Code.** The technical person shows you where it is the first time.

2. **Ask Claude where things stand:**

   ```text
   Where are we?
   ```

   Claude answers with what is in progress, what is waiting for a review and what needs cleaning
   up. Your pieces are in that answer: how many are waiting for a review, in progress or not
   started, and which ones need someone to act. On a new project the list is short or empty. An
   answer means the setup works.

3. **Ask what you can do:**

   ```text
   I am on the marketing team and I do not use developer tools. What can I ask you to do in this project?
   ```

</Steps>

## If something is off

| What you see | What to do |
| --- | --- |
| Claude says it cannot reach GitHub, or asks you to sign in | Ask the technical person to redo step 1 of Part 1. |
| Claude says it cannot start a draft because the shared version (`develop` or `main`) does not exist | The git and GitHub part of the setup did not run. Ask the technical person to run `cckit init --yes` in the project folder (step 2 of Part 1). |
| In a new draft Claude does not know the roles, the brand voice skill or the plain-language mode | The setup files were never saved into the shared version. The fix is the same: `cckit init --yes` in the project folder, then start the draft again. |
| Claude answers with developer terms you do not know | Say "Explain that in plain language." The words are on [Words you will hear](/marketing/words-you-will-hear/). |
| Claude asks permission to run something | Read what it says it will do. Creating a draft, saving your work and asking for a review are expected. If you are unsure, say no and ask it to explain. |

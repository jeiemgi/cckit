Every coloured tag in these docs says **how a thing is triggered**. A tag sits next to a heading or
a name, and its colour means the same on every page. This page first says what each tag means, then
is the directory: each tag explains **how you use it** and lists everything of that kind.

## The tags

<TagLegend />

## How to use them

- A page tagged <Tag kind="flow" /> describes a process you can run from start to finish.
- A name tagged <Tag kind="command" /> is something you type in a terminal.
- A name tagged <Tag kind="skill" /> is something you run inside Claude Code with a `/`.
- A name tagged <Tag kind="conversational" /> happens just by asking Claude in plain words.

You don't have to read top to bottom. Scan for the tag that matches what you want to do, and start
there.

## Conversational

<Tag kind="conversational" />

</div>

**How you use it:** say what you want to Claude Code in plain words — no command, no slash.
Asking to "contribute this upstream" starts the `kit-contribute` skill; "write docs for this" starts
`kit-docs-writer`. Claude matches your intent to the right skill.

## Command

<Tag kind="command" />

</div>

**How you use it:** type it in your terminal — `cckit <verb>` (for example `cckit start 42`). Run
`cckit help` for the full list, or `cckit <verb> --help` for one. Add `--llm` to any verb for
machine-readable output.

## Skill

<Tag kind="skill" />

</div>

**How you use it:** in Claude Code, type `/` then the skill name — `/kit-next`, `/kit-ship`. The
editor lists them as you type. Many skills *also* trigger conversationally (see above), so you can
either run `/kit-contribute` or ask to "contribute this upstream".

## Hook

<Tag kind="hook" />

</div>

**How you use it:** you don't — a hook runs **automatically** when an event happens (before a commit,
on session start, and so on). cckit wires them when you set up a repo; you see the result. The
Hooks page lists each one and the command it guards.

## Agent

<Tag kind="agent" />

</div>

**How you use it:** add `--llm` to any cckit verb to get machine-readable output (uniform data as
TOON, JSON otherwise) — this is the surface an agent reads instead of scraping human text. The
`AGENTS.md` contract documents it.

## Two tracks

The switch beside the site title moves between the site's two tracks.

| Track | For | Accent | Starts at |
| --- | --- | --- | --- |
| **Software** | developers who drive cckit from a terminal or from Claude Code | blue | [How an agency builds software](/software/) |
| **Marketing** | marketing teams who work by talking to Claude and never open a terminal | red | [What cckit does for a marketing team](/marketing/) |

Each track has its own sidebar. The Software sidebar follows the order a team works in: **Start
here**, **Philosophy**, **Getting started**, **Memory**, **Project management**, **Design**,
**Development**, **Review**, **Ship** and **Reference**. Only the group of the page you are on is
open. A Software page that is not in the sidebar is one click away on its area's "More guides" page
or on [All reference pages](/reference/), and search covers all of them.

The Marketing pages are also in Spanish: use the language picker in the top bar of any Marketing
page. Software pages are in English only.

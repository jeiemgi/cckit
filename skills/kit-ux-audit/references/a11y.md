# kit-ux-audit — a11y lane

Semantic-HTML and accessibility pass over a chosen scope. **Detection is `scripts/ux-a11y-scan.sh`**
(grep/perl, `$0`, macOS-safe) — **judgment is the model** (confirm the smell is a real defect,
map it to the correct element/pattern, prioritize). The scan flags *candidates* from static regex;
many need a one-line look at the file to confirm.

This is not a substitute for an axe / Lighthouse run against the rendered app — it catches the
structural mistakes that live in the source (wrong element, missing name, broken focus) before the
app is even running, which is exactly where they are cheapest to fix.

## 1 · Scope

Same options as the other lanes (whole app · route group · page · component · dir). Pass
`--exclude <regex>` to skip a second surface. For a page scope, include sibling screens so
heading-order and landmark checks compare like with like.

## 2 · Detect

```bash
scripts/ux-a11y-scan.sh <path> [--exclude <re>] > /tmp/ux-a11y.txt
```

Five groups, each `(N hits)` + `file:line` rows:

| § | Group | Looks for |
| --- | --- | --- |
| A1 | NON_SEMANTIC_INTERACTIVE | `onClick`/key handlers on `<div>`/`<span>`/`<li>`/`<tr>`; `role="button\|link\|tab…"` on a non-native element; redundant `role` on a native one |
| A2 | MISSING_TEXT_ALT | `<img>` with no `alt`; `<img alt="">` to confirm as decorative; icon-only `<svg>` with no name and no `aria-hidden` |
| A3 | UNLABELED_CONTROL | `<input>`/`<select>`/`<textarea>` with no `id` / `aria-label` / `aria-labelledby`; `<label>` with no `htmlFor`; icon-only `<button>` with no accessible name |
| A4 | HEADING_LANDMARK | `<h3+>` with no `<h1>`/`<h2>` in the file; multiple `<main>`; a landmark built as a styled `<div>`; `<section>`/`<article>` with no accessible name |
| A5 | FOCUS_KEYBOARD | positive `tabIndex`; `onMouseOver` with no `onFocus` twin; focus outline removed with no `:focus-visible`; `aria-hidden="true"` on something focusable; `autoFocus` |

For a large scope, fan classification out to read-only `Explore` sub-agents (one per group), each
briefed with this file.

## 3 · Judge

For each row decide: **DEFECT** (fix), **OK** (a false positive — say why in one clause), or
**NEEDS_VISUAL** (can't tell from source — e.g. is that `<div onClick>` also reachable another
way?). Map every DEFECT to the fix:

- **A1** → the native element. A thing that navigates is an `<a href>`; a thing that acts in place
  is a `<button type="button">`. A custom widget that must stay a `<div>` needs `role` **and**
  `tabIndex={0}` **and** an `onKeyDown` for Enter/Space **and** a visible focus style — all four,
  or it's a defect. Redundant `role` on a native element → delete the `role`.
- **A2** → `<img alt="…">` describing purpose, not appearance; truly decorative → `alt=""` **and**
  confirm it carries no information. Icon-only `<svg>` that conveys meaning → `role="img"` +
  `aria-label`; purely decorative → `aria-hidden="true"` and let the adjacent text carry it.
- **A3** → a programmatically associated `<label htmlFor={id}>` (visible label preferred over
  `aria-label`). Icon-only control → `aria-label` naming the action ("Delete row", not "trash").
- **A4** → one `<h1>` per page, no skipped levels (an `<h2>` may not jump to `<h4>`); real
  landmark elements (`<nav>`, `<header>`, `<main>` once, `<footer>`, `<aside>`); every `<section>`
  used as a region gets an `aria-labelledby` pointing at its heading (or an `aria-label`).
- **A5** → remove positive `tabIndex` (use `0` or `-1` and DOM order); pair pointer handlers with
  keyboard equivalents (`onFocus`/`onBlur`, `onKeyDown`); never suppress the focus ring without a
  `:focus-visible` replacement; `aria-hidden` never wraps a focusable node; drop `autoFocus`
  unless the screen exists only to take that one input.

**Cross-check the project's own rules** (`.claude/rules/*`) if present — many projects already
mandate "4 states", `focus-visible`, semantic landmarks, an icon set with `aria-hidden`. Cite the
slug in the finding when one applies.

## 4 · Findings

Emit the `findings.json` schema (`report.md`) with these heuristic ids:

| id | finding |
| --- | --- |
| `A1` | Non-semantic interactive element — what it is now → the element it should be |
| `A2` | Missing / wrong text alternative — element · what's missing |
| `A3` | Unlabeled form control or icon-only button — control · proposed label wiring |
| `A4` | Heading-order or landmark gap — file · the jump / the div-landmark / the unnamed region |
| `A5` | Focus / keyboard problem — the specific smell + the fix |

`severity`: `crit` a core action is keyboard-unreachable or a form control has no name ·
`p1` non-semantic interactive on a common path, missing `alt` on meaningful images, focus ring
removed · `p2` landmark/heading structure, decorative-alt confirmations · `p3` single-site polish.
`needs_visual: true` whenever the row can't be confirmed a defect from source alone.
